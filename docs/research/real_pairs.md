## Постановка

Трек делится на две половины с равной энергией голоса (A и B). Исходник — сухой A.
- **same**: референс = wet A (легкий случай, тот же фрагмент);
- **cross**: референс = wet B (другая часть песни, ближе к реальной работе).

Истинная цель в обоих вариантах — wet A, поэтому прямая ошибка валидна везде:
- `logmel` — средняя |Δ| log-mel (80 полос, по каждому каналу, дБ);
- `mrstft` — многоразрешающий лог-STFT по Mid (окна 512/2048/8192, дБ);
- `f0` — медиана |ΔF0| к wet A (центы, yin с вокализацией pyin).
Перед сравнением громкость выравнивается (−23 LUFS) и ищется задержка цепочки (±100 мс).

`wet_true` — сам wet A: его style_distance до референса — это «пол» метрики (в same он 0 по построению).

### Совпадает ли порядок режимов по style_distance и по прямой ошибке

Попарное сравнение режимов dry/model/optimizer/model+opt внутри каждого кейса (пары с разницей меньше
0.03 по style или 0.05 по прямой ошибке не считаются), τ Кендалла — среднее по кейсам:

| Вариант | style vs logmel | style vs mrstft | style vs f0 |
|---|---|---|---|
| same | 19 из 31 (61%), τ = +0.17 | 9 из 25 (36%), τ = −0.08 | 11 из 22 (50%), τ = −0.03 |
| cross | **10 из 36 (28%), τ = −0.39** | 7 из 31 (23%), τ = −0.33 | 22 из 23 (96%), τ = +0.66 |

Лучший режим по кейсам (из dry/model/optimizer/model+opt):
- по style: same — dry 5, optimizer 3; cross — optimizer/model+opt 7, model 1;
- по logmel: same — dry 6 из 8; cross — dry 7 из 8.

## Выводы

1. **На реальной обработке метрика стиля следит за разницей только тогда, когда разница большая.**
   Whiptails (реверб + стерео + тюн, style dry↔wet 8.35): оба режима с CMA-ES снижают и style (8.3 → 0.45),
   и прямую ошибку (logmel 11.5 → 8.0–8.7), здесь порядок совпадает. На тонкой обработке (лента, тюн —
   style dry↔wet 0.14–0.63) метрика и прямая ошибка расходятся.
2. **В cross-варианте style_distance ранжирует режимы против прямой спектральной ошибки** (28% совпадений,
   τ = −0.39). Причина видна в столбце `wet_true`: расстояние истинного результата до референса из другой
   части песни — 1.07–1.93, то есть «пол» метрики между двумя частями одной и той же обработки больше, чем
   разница dry↔wet на одном фрагменте (0.14–0.63). Без Whiptails wet_true ближе к референсу, чем сухой
   исходник, в среднем всего на 0.11 (в 2 из 7 — не ближе вовсе), а optimizer в 3 из 8 уходит ниже wet_true (oxeye_backing1: style 0.84 при поле 1.52,
   а logmel вырос 0.70 → 3.88 дБ — EQ, компрессор и дилей подгоняют содержание фрагмента, а не обработку).
   Этот «пол» на 27% из LTAS, 19% decay_fast, 15% sib_p90, 13% reverb_tail — признаки, которые зависят от
   того, что и как спето в фрагменте.
3. **Тюн метрика ранжирует правильно, когда pyin его видит**: в cross style и f0 согласны в 22 из 23
   сравнений; pitch_corrector снижает ошибку F0 к истинному тюну 10–14 → 5–8 ц. Но logmel/mrstft при этом
   растут (вероятно, PSOLA ведет ноты иначе, чем тюнер инженера, и добавляет артефакты), поэтому для тюна нужна своя
   прямая метрика F0, спектральная ее не заменяет. В oxeye_leadvox тюн не включился вовсе.
4. **Лучший режим**: optimizer ≈ model+optimizer. В 14 из 16 кейсов цепочки полностью одинаковые — на этих
   парах модель не включает плагинов сверх правил, и ее старт не меняет итог. Различие только на Whiptails:
   model+opt немного лучше по logmel (8.03 против 8.73 в cross). Режим model без подбора — худший на
   единственной паре с крупной обработкой (style 6.6, logmel хуже сухого: 11.6–11.8 против 11.5;
   предсказывает distortion+chorus вместо реверба и стерео).
5. **Ни один режим не «не навредил»**: в same-take на oxeye dry ближе к wet по style, чем любой результат
   (0.09 против 0.17 на oxeye_leadvox). Рендер всегда применяет подавление резонансов и EQ по референсу, даже
   когда исходник уже совпадает с целью; по logmel сухой исходник лучший в 6 из 8 same и 7 из 8 cross.

## Ограничения

- Мало данных: 8 пар из 3 песен, из них 6 — один тюн одной песни; итоги нельзя усреднять как независимые.
- **Модель видела эти голоса**: все три песни в train-сплите, а обработанные файлы попадали в dataset_v2/v3
  как «сухие» (692 из 30000 сэмплов v3: 356 как исходник, 333 как голос референса, 3 оба). Исключены из пула
  (`PROCESSED_VOCAL_STEMS` в `app/dataset/dataset_generator.py`), датасет нужно перегенерировать.
- Один seed; фрагменты 8–19 с. Whiptails без измеримого тюна.
